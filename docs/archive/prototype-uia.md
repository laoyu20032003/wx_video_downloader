## 1. 背景

当时要回答三个问题：

1. 作者主页头部写“163 条原创内容”，是不是只有 163 张卡？
2. 能不能不用人工滚鼠标，把整个作者主页翻完？
3. 每张卡的封面能不能显示在 viewer 里？

## 2. 实测：163 ≠ 列表总数

```text
页面标注：163 条原创内容
顺序翻页采集：321 张
页数：33
最后一张：致自己的一段话（index 320）
```

结论：

> **163 是“发布时勾选原创声明且审核通过”的作品数，不是主页作品总数。**
>
> 主页作品列表只统计该账号自己上传发布的内容，不包含转发、别人的视频或别人的收藏。
> 321 = 该账号自己发布的全部作品（原创 + 未声明原创；也包含图片动态、图文、直播回放等非原创标记内容）。

所以：

- 不能拿 163 截断；
- 不能按 163 预留空槽；
- 全量列表应以实际滚动发现数为准；
- 只要原创内容，需要原创标识或元数据过滤，不能靠数字截断。

后续在同一账号的另一轮实测又出现过 330、434 等数字，说明列表数量会随账号内容/加载状态变化，但“163 不是总数”这个结论不变。

## 3. 滚屏结论（2026-11-16）

```text
page-profile 数量 = 1
click-box 卡片 = 315
可见卡片 = 10
ScrollPattern = 不可用
滚轮后 Y 整体移动 500px
```

行为：

- `page-profile` 没有可用的 `ScrollPattern`；
- 自动滚屏只能靠鼠标滚轮；
- UIA 树里保留大量视口外/历史节点；
- 每滚一屏，读取与 `page-profile` 视口相交的卡片；
- 按 `时长|点赞|文案` 指纹增量合并；
- 连续两页无新增就停止；
- 结束后滚回顶部。

## 4. 封面

UIA 不暴露图片二进制，只有封面矩形。原型按 `cover` 矩形做屏幕截图：

```text
prototype/work/covers_uia/<key-hash>.jpg
```

正式 viewer 沿用这个方案，保存到：

```text
viewer/work/covers_uia/
```

限制：

- 微信必须在最前面；
- viewer 不能遮住卡片区域，否则会截到别的窗口；
- 只在该卡片可见时才能截；
- 截图尺寸就是卡片封面大小，不是原图；
- 原图要从内存的 `coverUrl/20304` 取，覆盖率和 oid 映射不完整。

## 5. 已知限制

- 321/315 个节点不等于 163 条原创；
- 主页总作品数大于原创数，且可能含图片/图文/直播回放；
- 重复时长、重复文案会误合并；
- 滚动依赖微信前台和鼠标位置；
- 自动滚屏会移动用户当前页面；
- 下载仍受“明文 MP4 头是否在内存”限制。

## 6. 归档后保留的诊断

```powershell
pwsh -Sta -File tools\uia-scroll-probe.ps1 -Steps 6
```

它会：

- 找活动 `page-profile`；
- 统计 `click-box` / 可见卡片 / 去重数；
- 滚轮前后 Y 变化；
- 输出 `work/scroll_probe.json`。

正式全量采集、封面、跨层绑定、逐行下载都在：

```text
viewer/
```
